# CLAUDE.md

Этот файл читается Claude Code в начале каждой сессии. Здесь — постоянный контекст проекта.

## О проекте

**Running Ecosystem** — мобильное приложение и экосистема для полупрофессиональных бегунов. Команда: 2 разработчика. Текущая стадия — Phase 0 (выбор фреймворка) или Phase 1 (Territory Core) — см. `STATUS.md`.

## Документы, которые ты ВСЕГДА читаешь перед задачей

1. **`docs/RUNNING_ECOSYSTEM_TZ.md`** — техническое задание: требования, архитектура, ограничения, доменная модель, картографический стек
2. **`docs/DEVELOPMENT_PLAN.md`** — план разработки: фазы, задачи с ID, зависимости, acceptance criteria
3. **`STATUS.md`** (в корне) — текущий статус: какая фаза, какие задачи в работе, какие закрыты
4. **`docs/DECISIONS/`** — папка с ADR (Architecture Decision Records). Любое значимое решение фиксируется здесь

## Правила работы

### Перед началом любой задачи
1. Прочитай задачу по её ID в `DEVELOPMENT_PLAN.md`
2. Проверь `Depends on` — закрыты ли зависимости (см. `STATUS.md`)
3. Прочитай связанные разделы ТЗ (ссылки в задаче через §)
4. Если задача неоднозначна — задай уточняющий вопрос, **не догадывайся**

### Принципы кода (из ТЗ §3)
- **Domain-driven** — доменная модель чистая, без зависимостей от UI и БД
- **Sensor-agnostic** — GPS один из источников, не "тот самый". Всегда через `LocationAdapter`
- **MapAdapter абстракция** — никогда не импортируй Mapbox SDK напрямую в доменный/бизнес код. Только через интерфейс `MapAdapter`
- **Offline-first** — клиент работает без сети
- **Multi-tenant с дня 1** — даже если сейчас один пользователь, в схеме есть `user_id`

### Что НЕ делать никогда
- Не импортировать Mapbox SDK напрямую в коде вне `src/map/adapters/`
- Не считать площадь по lat/lon напрямую — обязательно проекция в локальную плоскость (см. ТЗ §6.6)
- Не использовать `PolylineAnnotation` / `AnnotationManager` для трека — только `LineLayer + GeoJsonSource` (см. ТЗ §10.5)
- Не коммитить секреты — токены идут через `.env` / native keystore
- Не пропускать unit-тесты для pipeline и area calc (целевое покрытие 80%+ и 90%+)

### Структура папок (Phase 1)
```
src/
  domain/        # сущности, value objects, ничего платформенного
  pipeline/      # GPS pipeline (фильтры, kalman)
  map/           # MapAdapter и реализации
  location/      # LocationAdapter и реализации
  storage/       # репозитории, SQLite
  state/         # store(s)
  ui/            # экраны, компоненты
  util/          # хелперы
```

### Когда закрываешь задачу
1. Все acceptance criteria из `DEVELOPMENT_PLAN.md` пройдены
2. Тесты написаны и зелёные
3. Линтер чистый
4. Обнови `STATUS.md`: переведи задачу из `IN_PROGRESS` в `DONE`
5. Если приняты значимые решения — создай ADR в `docs/DECISIONS/`

## Стек

- **Mobile:** определится после Phase 0 (Expo RN или Flutter)
- **Карта:** Mapbox (см. ТЗ §10)
- **Backend:** Go (основное), C++/Rust (горячие пути), Python (модели)
- **БД:** PostgreSQL + TimescaleDB + ClickHouse + Redis
- **Брокер:** NATS JetStream
- **Деплой:** K8s, Helm, ArgoCD

## При неуверенности

Если ты не уверен в решении — **спроси команду**, не делай молча. Особенно по темам:
- Изменение публичного API
- Изменение схемы БД
- Изменение интерфейса MapAdapter / LocationAdapter
- Выбор библиотек, не упомянутых в ТЗ
- Любые отступления от плана разработки
