## Deploy procedure (re-runnable from a fresh shell)

```bash
# 1. Sync source from a git checkout on your laptop.
cd ~/Desktop/projects/sport
rsync -az --exclude='.env*' --exclude='node_modules' --exclude='.git' \
  --exclude='_archive' --exclude='__pycache__' \
  services/backend/ root@82.25.71.215:/opt/running-ecosystem/

# 2. On first deploy only: generate .env.prod on the server.
#    Secrets are generated in-place; never echoed; perms 0600.
ssh root@82.25.71.215 'umask 077 && cd /opt/running-ecosystem && {
  echo "# Generated $(date -Iseconds). NEVER commit. chmod 600."
  echo "SPORT_STACK_TAG=local"
  echo "POSTGRES_PASSWORD=$(openssl rand -base64 32 | tr -d /=+\n)"
  echo "JWT_SECRET=$(openssl rand -base64 48 | tr -d /=+\n)"
  echo "MINIO_ROOT_USER=re_minio_admin"
  echo "MINIO_ROOT_PASSWORD=$(openssl rand -base64 32 | tr -d /=+\n)"
  echo "CADDY_ACME_EMAIL=noreply@local.invalid"
} > .env.prod && chmod 600 .env.prod'

# 3. Build all 8 service images on the server (no GHCR; SPORT_STACK_TAG=local).
#    ~3-4 min on cold cache, < 30s on warm cache.
ssh root@82.25.71.215 'cd /opt/running-ecosystem && \
  docker compose \
    -f docker-compose.prod.yml \
    -f docker-compose.deploy.yml \
    --env-file .env.prod build'

# 4. Bring stack up. Migrations run as init job (golang-migrate).
ssh root@82.25.71.215 'cd /opt/running-ecosystem && \
  docker compose \
    -f docker-compose.prod.yml \
    -f docker-compose.deploy.yml \
    --env-file .env.prod up -d'

# 5. Smoke test.
curl -sk https://82-25-71-215.sslip.io:8444/healthz
# → {"status":"ok"}
curl -sk -X POST -H 'Content-Type: application/json' \
  -d '{"email":"probe@example.com"}' \
  https://82-25-71-215.sslip.io:8444/auth/request-code
# → 202 {}
```

```bash

  docker compose -f docker-compose.prod.yml -f docker-compose.deploy.yml \
    --env-file .env.prod down -v'

# Drop `-v` to preserve data.
```

## Cert trust — known limitation

Caddy issues a self-signed cert (`Caddy Local Authority - ECC Intermediate`).
Real Let's Encrypt is blocked on this server because:
- HTTP-01 challenge → casino nginx owns :80
- TLS-ALPN-01 challenge → casino nginx owns :443
- DNS-01 challenge → sslip.io has no DNS API

**Mobile app on a real device will reject the cert by default.** Options for
closed-beta testers (5-10 people):

1. **Install Caddy root CA as Android user trust anchor** (per tester).
   Get the root: `ssh root@82.25.71.215 'docker exec re_gateway cat /data/caddy/pki/authorities/local/root.crt'`.
   Send to tester → Android Settings → Security → Encryption & credentials →
   Install a certificate → CA certificate.

2. **Bundle a `network_security_config.xml` in the RN app** that allows
   trust of user-installed CAs (Android 7+ ignores user CAs by default for
   apps targetSdk ≥ 24).

Backlog item: `REAL-CERT-FOR-BACKEND` (v1.0.1) — get a real DNS name with
LE on a port that doesn't conflict with casino (DNS-01 via Cloudflare /
deSEC / etc.).

## Co-tenant safety invariants

These must hold on every deploy. If any breaks, **stop and investigate** —
casino is a separate revenue stream owned by the same operator.

- [ ] `/opt/casino/` is never touched.
- [ ] The `niko-prod` compose project containers are not restarted.
- [ ] nginx on `:80`/`:443` is not modified (verify with `ss -tlnp | grep -E ':80|:443'` — both should still be nginx PIDs).
- [ ] Our Caddy binds only to `:8444`. Verify before exposing: `ss -tlnp | grep :8444` should show our caddy.
- [ ] Our docker network is its own (`running-ecosystem_default`); does not attach to `niko-prod_*` networks.
