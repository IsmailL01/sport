## Deploy procedure (re-runnable from a fresh shell)

```bash
# 1. Sync source from a git checkout on your laptop.
cd ~/Desktop/projects/sport
rsync -az --exclude='.env*' --exclude='node_modules' --exclude='.git' \
  --exclude='_archive' --exclude='__pycache__' \
  services/backend/ root@82.25.71.215:/opt/running-ecosystem/

# 2. On first deploy only: generate .env.prod on the server.
#    Secrets are generated in-place; never echoed; perms 0600.
ssh root@82.25.71.215 'umask 077 && cd /opt/running-ecosystem && {
  echo "# Generated $(date -Iseconds). NEVER commit. chmod 600."
  echo "SPORT_STACK_TAG=local"
  echo "POSTGRES_PASSWORD=$(openssl rand -base64 32 | tr -d /=+\n)"
  echo "JWT_SECRET=$(openssl rand -base64 48 | tr -d /=+\n)"
  echo "MINIO_ROOT_USER=re_minio_admin"
  echo "MINIO_ROOT_PASSWORD=$(openssl rand -base64 32 | tr -d /=+\n)"
  echo "CADDY_ACME_EMAIL=noreply@local.invalid"
} > .env.prod && chmod 600 .env.prod'

# 3. Build all 8 service images on the server (no GHCR; SPORT_STACK_TAG=local).
#    ~3-4 min on cold cache, < 30s on warm cache.
ssh root@82.25.71.215 'cd /opt/running-ecosystem && \
  docker compose \
    -f docker-compose.prod.yml \
    -f docker-compose.deploy.yml \
    --env-file .env.prod build'

# 4. Bring stack up. Migrations run as init job (golang-migrate).
ssh root@82.25.71.215 'cd /opt/running-ecosystem && \
  docker compose \
    -f docker-compose.prod.yml \
    -f docker-compose.deploy.yml \
    --env-file .env.prod up -d'

# 5. Smoke test.
curl -sk https://82-25-71-215.sslip.io:8444/healthz
# → {"status":"ok"}
curl -sk -X POST -H 'Content-Type: application/json' \
  -d '{"email":"probe@example.com"}' \
  https://82-25-71-215.sslip.io:8444/auth/request-code
# → 202 {}
```

## Cert trust — known limitation

Caddy issues a self-signed cert (`Caddy Local Authority - ECC Intermediate`).
Real Let's Encrypt is blocked on this server because:
- HTTP-01 challenge → casino nginx owns :80
- TLS-ALPN-01 challenge → casino nginx owns :443
- DNS-01 challenge → sslip.io has no DNS API

**Mobile app on a real device will reject the cert by default.** Options for
closed-beta testers (5-10 people):

1. **Install Caddy root CA as Android user trust anchor** (per tester).
   Get the root: `ssh root@82.25.71.215 'docker exec re_gateway cat /data/caddy/pki/authorities/local/root.crt'`.
   Send to tester → Android Settings → Security → Encryption & credentials →
   Install a certificate → CA certificate.

2. **Bundle a `network_security_config.xml` in the RN app** that allows
   trust of user-installed CAs (Android 7+ ignores user CAs by default for
   apps targetSdk ≥ 24).

Backlog item: `REAL-CERT-FOR-BACKEND` (v1.0.1) — get a real DNS name with
LE on a port that doesn't conflict with casino (DNS-01 via Cloudflare /
deSEC / etc.).

## Migrating to real LE certs

This server's stock deploy uses Caddy's self-signed local CA because LE is
blocked here (casino owns :80/:443; sslip.io has no DNS API). The escape
hatch is **DNS-01 via Cloudflare**, captured in
`gateway/Dockerfile` + `gateway/Caddyfile.le` + `docker-compose.deploy-le.yml`.

### Prerequisites (one-time, user-side)

1. **DNS name on a Caddy-supported DNS provider.** `basicworld.online` is on
   reg.ru which Caddy does NOT have a plugin for. Choose one path:
   - **(P-A)** Move `basicworld.online` DNS hosting to Cloudflare entirely
     (free; reg.ru remains registrar). 24-hour-ish propagation. Casino's
     existing DNS records have to be re-entered on Cloudflare before the
     NS switch. **Touches casino DNS** — coordinate.
   - **(P-B)** Subdomain NS delegation: keep `basicworld.online` on reg.ru;
     add `NS api.basicworld.online → cloudflare-ns-X.cloudflare.com`
     records at reg.ru pointing only the `api.*` subdomain to Cloudflare.
     Cloudflare hosts the `api.basicworld.online` zone separately. Casino
     root DNS untouched. **Recommended.**
   - **(P-C)** Buy a fresh domain on a Cloudflare-friendly registrar /
     use a free deSEC / DuckDNS subdomain. Cleanest separation; small cost
     or vendor lock-in.

2. **Cloudflare API token.** dash.cloudflare.com → My Profile → API Tokens
   → Create Token → custom template:
   - Permissions: `Zone — Zone — Read`, `Zone — DNS — Edit`
   - Zone Resources: Include — Specific zone — `<your zone>` (api.basicworld.online for P-B)

3. **Mobile rebuild.** Once LE issues a publicly-trusted cert, the
   `network_security_config.xml` domain-config additive trust is harmless
   but unnecessary; both `system` + Caddy local CA are listed for the
   backend hostname → system anchors will pick the LE cert chain
   automatically. **The cutover requires only `apps/mobile-rn/.env` change
   to the new hostname + an APK rebuild + redistribute.**

### Cutover procedure

```bash
# 1. Add new env vars to /opt/running-ecosystem/.env.prod on server.
ssh root@82.25.71.215 'umask 077 && cat >> /opt/running-ecosystem/.env.prod <<EOF
BACKEND_DOMAIN=api.basicworld.online
CLOUDFLARE_API_TOKEN=<token>
EOF'

# 2. Verify DNS resolves to 82.25.71.215.
dig +short A api.basicworld.online @1.1.1.1
# → 82.25.71.215

# 3. Bring the LE variant up (replaces existing gateway container only;
#    other 12 containers re-attach to the same volumes — zero data loss).
ssh root@82.25.71.215 'cd /opt/running-ecosystem && \
  docker compose -f docker-compose.prod.yml -f docker-compose.deploy-le.yml \
    --env-file .env.prod up -d --build gateway'

# 4. Watch first cert issuance (≤ 60s typically).
ssh root@82.25.71.215 'docker logs re_gateway --tail 30 -f'
# → look for "obtained certificate" lines for both BACKEND_DOMAIN
#   and s3.BACKEND_DOMAIN.

# 5. Smoke test WITHOUT -k (cert is now publicly trusted).
curl -s https://api.basicworld.online:8444/healthz
# → {"status":"ok"}

# 6. Update mobile .env and rebuild APK.
sed -i '' 's|82-25-71-215.sslip.io:8444|api.basicworld.online:8444|g' \
  apps/mobile-rn/.env
```

After cutover, `Caddyfile.server` + `docker-compose.deploy.yml` remain in
the repo as the fallback for environments where DNS is unavailable.
