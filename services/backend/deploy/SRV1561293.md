## Stock (tls internal) fallback — `docker-compose.deploy.yml`

For environments where DNS is unavailable (e.g. a brand-new VPS before
DNS records propagate). Uses `Caddyfile.server` + stock `caddy:2.8-alpine`
+ `tls internal` self-signed CA.

```bash

#   1. rsync source as above
#   2. Generate .env.prod (umask 077, secrets piped silently):
ssh root@82.25.71.215 'umask 077 && cd /opt/running-ecosystem && {
  echo "# Generated $(date -Iseconds). NEVER commit. chmod 600."
  echo "SPORT_STACK_TAG=local"
  echo "POSTGRES_PASSWORD=$(openssl rand -base64 32 | tr -d /=+\n)"
  echo "JWT_SECRET=$(openssl rand -base64 48 | tr -d /=+\n)"
  echo "MINIO_ROOT_USER=re_minio_admin"
  echo "MINIO_ROOT_PASSWORD=$(openssl rand -base64 32 | tr -d /=+\n)"

#   3. Build:
```

## Cert trust — RESOLVED 2026-05-26 via DuckDNS

Initially deployed with Caddy `tls internal` self-signed CA because:
- HTTP-01 → casino nginx owns :80
- TLS-ALPN-01 → casino nginx owns :443
- DNS-01 → sslip.io has no DNS API

Solution: registered `messenger-am.duckdns.org` on DuckDNS (free), bumped
Caddy to 2.10 builder (DuckDNS plugin requires Go ≥ 1.24), obtained
wildcard cert `*.messenger-am.duckdns.org` via DNS-01. Mobile uses
`api.messenger-am.duckdns.org` (covered by wildcard); MinIO presigned
URLs use `s3.messenger-am.duckdns.org` (also covered). System trust
on Android picks up the chain automatically — no extra setup required
by testers.

## How LE is wired (current production, FYI)

DuckDNS allows a single TXT record per subdomain at the apex (e.g.
`_acme-challenge.messenger-am.duckdns.org`). It does NOT allow setting
TXT on `_acme-challenge.s3.messenger-am.duckdns.org` (each subdomain is
a separate logical entity in the DuckDNS account, with no support for
sub-sub TXT records).

**Workaround:** ONE multi-SAN wildcard cert `*.messenger-am.duckdns.org`
covering all real subdomains we use. The apex `messenger-am.duckdns.org`
is NOT used — public-facing names are `api.*` (mobile API) and `s3.*`
(MinIO).

```
       ┌─────────────────────┐
       │  Caddy on :8444     │
       │  wildcard LE cert   │
       └─────────────────────┘
            │       │
   ┌────────┴──┐ ┌──┴────────┐
   │ api.*     │ │ s3.*      │   ← @host matchers route the request
   │ → 8 svcs  │ │ → MinIO   │
   └───────────┘ └───────────┘
   anything else → 404
```

Renewal: Caddy auto-renews ~30 days before expiry, using the same DuckDNS
API token. No human intervention needed.

### Switching to a different DNS provider

If/when DuckDNS is dropped (or `basicworld.online` becomes hostable on a
Caddy-supported provider — Cloudflare, Route53, deSEC, Gandi, …):

1. Edit `gateway/Dockerfile` — replace `--with github.com/caddy-dns/duckdns`
   with the new plugin (e.g. `caddy-dns/cloudflare`).
2. Edit `gateway/Caddyfile.le` — swap `dns duckdns {env.DUCKDNS_API_TOKEN}`
   for the equivalent provider directive.
3. Update `.env.prod` env var names + values.
4. Update the BACKEND_DOMAIN env to the new hostname.
5. Wipe ACME state (one-liner above) and restart gateway.
6. Update mobile `apps/mobile-rn/.env` to the new `api.*` URL, rebuild APK.
