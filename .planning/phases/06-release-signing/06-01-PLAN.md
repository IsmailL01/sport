<claude_discretion_swaps>
This plan applies 3 RESEARCH §"Claude's Discretion" swaps that OVERRIDE specific
CONTEXT D-NN wording. Executor MUST honor the swaps:

1. **CONTEXT D-04 keystore format `JKS` → use `PKCS12`** (RESEARCH §4 + Assumption A6).
   Reason: PKCS12 is keytool default since JDK 9; Android Gradle Plugin accepts both
   transparently; no functional difference; modern portability. Keytool flag:
   `-storetype PKCS12` (not `-storetype JKS`).

2. **CONTEXT D-07 USB encryption `VeraCrypt` → use macOS Disk Utility encrypted DMG
   (AES-256 via `hdiutil create -encryption AES-256`)** (RESEARCH §6 + Assumption A7).
   Reason: VeraCrypt on macOS 26 (Tahoe) needs FUSE-T install with partial-SIP-disable
   on some Apple Silicon configs; encrypted DMG is native, no kernel-extension drama,
   same AES-256 primitive. The "2 USBs at 2 separate locations" structure stays
   identical — only the encryption container format changes.

3. **CONTEXT D-15(d) shell-piped `sops --set "$(base64 ...)"` → use `sops set
   --value-file /tmp/b64.txt` (SOPS ≥ 3.11)** (RESEARCH §7 Pitfall 7). Reason: avoids
   shell-history exposure + ARG_MAX risk. Use `--value-file` for ALL binary base64
   writes (keystore_base64 + later distribution_cert_p12_base64 + provisioning_profile_base64
   + asc_api_key_p8_base64). Short-string fields (passwords, alias, IDs) keep the
   shell-arg form (`sops set <file> '["a"]["b"]' "$VAR"`).

4. **macOS lacks working `shred` / `rm -P` on APFS** (RESEARCH Pitfall 11). The
   "delete plaintext keystore after encryption" step uses **RAM disk via `hdiutil`**
   (Pattern 1) — NOT `/tmp/` + `shred`. RAM disk evaporates on unmount, zero SSD
   trace.
</claude_discretion_swaps>

| Plaintext password ↔ shell history | All passwords passed via env var + `:env` keytool flag; never `-storepass <literal>`; `unset` after use |

| Encrypted DMG ↔ password | DMG password lives in 1Password sealed entry + on laminated recovery cards as mnemonic hint ONLY (never the password literal) |
| USB-A physical location ↔ USB-B physical location | 2 separate locations (D-07); single-point-of-failure broken |
