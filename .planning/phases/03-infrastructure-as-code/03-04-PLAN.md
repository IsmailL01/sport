    ## 8. Backup procedure (defensive — perform ДО cutover/upgrade)

    Backup существующего state из 148.253.214.156:

    ```
    ssh root@148.253.214.156 << 'EOF'
      cd /opt/sport/services/backend
      mkdir -p /var/backups/sport-prep
      docker compose -f docker-compose.prod.yml exec -T postgres pg_dump -U re running_ecosystem | gzip > /var/backups/sport-prep/postgres-$(date +%Y%m%d-%H%M).sql.gz
      docker run --rm -v backend_minio_data:/data -v /var/backups/sport-prep:/backup alpine tar czf /backup/minio-$(date +%Y%m%d-%H%M).tar.gz /data
      docker run --rm -v backend_caddy_data:/data -v /var/backups/sport-prep:/backup alpine tar czf /backup/caddy-data-$(date +%Y%m%d-%H%M).tar.gz /data
      cp /opt/sport/.env /var/backups/sport-prep/env-$(date +%Y%m%d-%H%M).backup 2>/dev/null || true
      ls -la /var/backups/sport-prep/
    EOF
    ```

    **Critical:** Phase 7 (DB-01..02) wraps это в pgBackRest automatic + restore drill. v1.0 Phase 3 cutover uses this manual snapshot как defensive safety net.
