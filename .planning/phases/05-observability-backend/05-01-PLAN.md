<objective>
Provision a SEPARATE VPS for Sentry self-hosted (per D-01 isolation redline) and lay down the Ansible foundation that Wave 2 (Plan 05-02) will use to install Sentry on top. This plan does NOT install Sentry itself — it ships the inventory + roles + Caddy config + UFW policy + sentry-prep role skeleton + first-boot smoke (Caddy serving placeholder HTTP 200 on sentry.<ip>.sslip.io with a valid Let's Encrypt cert).

Purpose: OBS-01 acceptance gate (Sentry self-hosted on a SEPARATE VPS at sentry.<sentry-ip>.sslip.io with its own ACME cert) requires (a) a real VPS provisioned by the user, (b) Ansible bootstrap that reuses Phase 3 common+docker+ufw roles verbatim, (c) Caddy in front per RESEARCH §1.4 (Sentry's bundled nginx rebound to 127.0.0.1:8080), (d) UFW policy that allow-lists the prod VPS for the future Loki push endpoint (D-28). Wave 2 then drops `getsentry/self-hosted@26.5.0` into /opt/sentry/ and runs install.sh.

Output: An SSH-reachable, hardened, Caddy-serving sentry VPS plus a fully-templated sentry-prep Ansible role (idempotent; install.sh `creates:` guard per RESEARCH P14). After Plan 05-01 closeout, `curl -fsSI https://sentry.<sentry-ip-dashed>.sslip.io/` returns HTTP 200 from a Caddy "Hello from sentry VPS" placeholder page with a Let's Encrypt cert in chain.
</objective>
