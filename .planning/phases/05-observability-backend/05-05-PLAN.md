<objective>
Wire OpenTelemetry OTLP/HTTP traces + sentry-go SDK into all 9 backend services. Both use the same Sentry prod-backend project (single project per RESEARCH §1.9 — services discriminated via `setTag("service",...)`). OTel spans pass through a custom SpanProcessor that strips PII attributes — reuses `PIIDenyList` from Plan 05-03 as the single source of truth (D-21).

Purpose: Two of Phase 5's eight ROADMAP success criteria depend on this plan:
- **Criterion 1 production usage** ("Sentry running at sentry.<host>" — Plan 05-01 + 05-02 stood it up; this plan makes services actually USE it for error reports + traces).
- **Criterion 5 (parity)** ("No GPS coords / phone numbers in logs" — Plan 05-03 covered logs; this plan extends the same scrub to OTel span attributes per D-21).

Output: When an exception is thrown in any of 9 services, sentry-go SDK captures it and POSTs to https://sentry.<host>/api/<project_id>/store/ tagged with `service=<svc>` + `env=prod` + `release=<git-sha>`. When an HTTP request enters any service, an OTel root span is created + exported via OTLP/HTTP to Sentry's OTLP receiver — PII attributes scrubbed before export.

Note: Plan 05-06 still wires DebugSessionMiddleware + Alloy log shipping + final acceptance walkthrough; this plan does NOT close the phase. After Plan 05-05 lands, only OBS-08 backend seam + OBS-06 runtime probe + Phase closure remain.
</objective>
