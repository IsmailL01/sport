`middleware.go`: Export `Middleware`. Returned handler logic:
1. If `r.URL.Path` matches any entry in `p.SkipPaths` (exact prefix match) → call `next.ServeHTTP` immediately.
2. Read `r.Header.Get("X-Client-Version")`. If empty → `log.WarnContext(r.Context(), "clientversion: missing header", "path", r.URL.Path)` → call `next.ServeHTTP` (graceful per D-08).
3. Call `Parse(header)`. On err → `log.Warn(... "clientversion: malformed header", "value", header, "err", err)` → call `next.ServeHTTP` (graceful per RESEARCH §Pitfalls #5).
4. Compare parsed semver to `p.MinSupported` via `semver.Compare("v"+parsedSemver, "v"+p.MinSupported)`. If < 0 → write 426 with the JSON body, set `Content-Type: application/json`; **do not** call `next.ServeHTTP`.
5. Otherwise → attach parsed version to `r.Context()` via a typed context key and call `next.ServeHTTP`.

`parse_test.go`: table-driven tests for cases 1-6. `middleware_test.go`: tests 7-12. Use `httptest.NewRecorder` + a stub `next` handler that counts invocations. For 426 cases, JSON-decode the response body and assert keys/values. For log-warn cases, inject `slog.New(slog.NewTextHandler(&buf, nil))` and grep the buffer for the scope tag.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Mobile client → Caddy → backend services | Untrusted input crosses here; X-Client-Version is a client-supplied header |
| 426 response body → mobile force-update screen | URLs in response control where users are sent for "update now" |
| Caddy reverse_proxy → backend service | Header passthrough boundary; default Caddy preserves headers but custom directives could mangle |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-B-01 | Spoofing | X-Client-Version header (client-supplied) | accept | Header is a soft compatibility hint, not an auth claim. Worst case: attacker stamps a higher version to bypass force-update — they still hit the same backend handlers (no privilege escalation). v1.0 graceful-degrade philosophy explicitly accepts this. v1.1 may add signed version attestation if needed. |
| T-01-B-02 | Tampering | X-Client-Version header value parsing | mitigate | `Parse()` strictly validates semver shape via `semver.IsValid("v"+s)`. Malformed input → graceful pass-through with `slog.Warn`, NOT a 500 or crash. Test 4-6 cover empty/garbage/incomplete. No string interpolation into log fields (slog uses key-value, not format strings). |
| T-01-B-03 | Repudiation | Force-update event provenance | accept | 426 responses are stateless; no audit trail needed for v1.0. Mobile-side Sentry breadcrumbs (Phase 17) will capture force-update encounters. |
| T-01-B-04 | Information disclosure | 426 response body | mitigate | Body contains only public values: `min_version` (already public via mobile binary) and force_update URLs (already public — App Store / VPS manifest endpoint). No PII, no tokens, no internal hostnames. |
| T-01-B-05 | Denial of service | clientversion.Middleware on every request | mitigate | Parse is O(len(header)) with bounded len (HTTP header size cap enforced by net/http server config). `semver.Compare` is constant-time for fixed-shape inputs. No regex backtracking. Test 12 confirms behavior on adversarial-looking inputs (build suffix). |
| T-01-B-06 | Denial of service | force-update URL injection | mitigate | `forceUpdateUrl` comes from server response body, which is the same trusted backend. Mobile passes it to `Linking.openURL` (RN handles URL parsing; deeplink scheme allowlist is OS-enforced). If a malicious actor compromised the backend they could redirect users — but they could already do worse with full backend access; not a new attack vector. v1.1 may validate URL origin matches app's known update channels (TestFlight host, Caddy `/android/manifest.json` path). |
| T-01-B-07 | Elevation of privilege | Skip paths (`/healthz`, `/metrics`) | mitigate | Hardcoded list in main.go (env-overridable). `/healthz` returns liveness only (no auth needed for monitoring); `/metrics` is bound to non-public listener at Caddy level (not exposed externally per ROADMAP Phase 5 OBS-05). No business endpoints in skip list. |
| T-01-B-08 | Spoofing | Caddy reverse_proxy header passthrough | mitigate | Task 1 Subtask C explicitly verifies Caddyfile + Caddyfile.prod don't strip the header. If a future Caddy config adds a header-stripping directive, the integration test script will catch it (regression coverage). |
