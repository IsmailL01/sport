# ADR-0007: v1.0 Release Contract

**Дата:** 2026-05-15
**Статус:** Accepted
**Контекст:** Phase 1 / REL-01..05 (милестон v1.0 Production Readiness)
**Решение:** OpenAPI 3.1.0 hand-written YAML как контракт mobile↔backend; `X-Client-Version` HTTP header + HTTP 426 force-update для version negotiation; Postgres-backed `pkg/featureflags` (boolean + percent rollout, FNV-1a hash) + offline-first mobile mirror для feature flags. SCP-throughout — cross-cutting deploy principle.

## Контекст

Phase 1 redefined-milestone v1.0 — это **shared design contract** между backend
(Phase 2..8 hardening) и mobile (Phase 9..17 release-builds). Без зафиксированного
контракта обе ветки расходятся: backend может молча сменить URL/payload, mobile
может не подхватить 426 force-update, feature flag matrix может разъехаться между
сервисами.

Канонические требования:

- [.planning/REQUIREMENTS.md](../../.planning/REQUIREMENTS.md) §Phase 1 — Release Contract & Version Baseline (REL-01..05).
- [.planning/ROADMAP.md](../../.planning/ROADMAP.md) §Phase 1.
- [.planning/phases/01-release-contract-and-version-baseline/01-CONTEXT.md](../../.planning/phases/01-release-contract-and-version-baseline/01-CONTEXT.md) — гэйп-анализ + 14 решений (D-01..D-22) принятых в auto-mode.
- [.planning/phases/01-release-contract-and-version-baseline/01-RESEARCH.md](../../.planning/phases/01-release-contract-and-version-baseline/01-RESEARCH.md) — confidence claims (HIGH на Standard Stack, HIGH на Architecture, MEDIUM на Pitfalls).

Этот ADR пишется **первым** среди трёх Phase 1 планов (Plan 01-01) per orchestrator
strategy (a): subsequent plans (01-02 version negotiation; 01-03 feature flags)
ссылаются на locked design. Amendments допускаются если 02/03 surface meaningful
архитектурные сюрпризы.

## Решение

Три тесно связанных архитектурных sub-decision'а зашиты в один ADR (per CONTEXT
D-20 — splitting в 0007/0008/0009 создаёт ADR sprawl при том, что три раздела
делят инфраструктуру).

### §1 API Contract Format

**Принято:** OpenAPI 3.1.0 hand-written YAML, один файл per service, shared
components в `services/backend/api/_shared/`, validation через `redocly lint`,
route-vs-spec drift через Go AST tool (`scripts/openapi-routes-check`). **Никакого
codegen toolchain'а в v1.0.**

**Coverage:** mobile-facing endpoints only — internal NATS pub/sub, прямой gRPC
service-to-service, cron-job APIs — НЕ документируются в v1.0 (см. CONTEXT D-02;
internal contracts — v1.1).

**Файлы:**

- `services/backend/api/identity.yaml` (existing, Phase 2 / P2-A-02 pattern; в v1.0.x cleanup мигрируем nullable→3.1-syntax + `$ref` на `_shared/`).
- `services/backend/api/activity-sync.yaml` (existing, same).
- `services/backend/api/feed.yaml`, `social-graph.yaml`, `messaging.yaml`, `realtime-gw.yaml`, `notifications.yaml`, `media.yaml`, `gateway.yaml` (созданы Plan 01-01).
- `services/backend/api/_shared/{schemas,parameters,responses}.yaml` — `Error`, `User`, `Cursor`, `Pagination`; `cursor`/`limit`/`sessionId`/`userId`/`flagName` params; `Unauthorized`/`Forbidden`/`NotFound`/`UpgradeRequired`/`RateLimited` responses.
- `services/backend/api/redocly.yaml` — lint config (`extends: [recommended]`; селективные relax'ы для v1.0; goal — tighten в v1.1).
- `services/backend/scripts/openapi-routes-check/` — Go AST tool (`mux.HandleFunc("METHOD /path", ...)` literal extraction → diff против YAML; exit 1 при drift). `make check-routes` target в `services/backend/Makefile`.

**Index doc:** [docs/API-CONTRACT-v1.0.md](../API-CONTRACT-v1.0.md) — per-service table + runbook.

### §2 Version Negotiation

**Принято:** `X-Client-Version` HTTP header + server-side compatibility map +
HTTP 426 Upgrade Required при client < min_supported.

**Транспорт:**

- Mobile: `apiClient.ts` штампует `X-Client-Version: <semver> (<build>)` на каждом запросе. Значение строится через `expo-application.nativeApplicationVersion` (semver) + `nativeBuildVersion` (build). Phase 1 (Plan 02) добавляет `expo-application@~7.0.8` в `apps/mobile-rn/package.json` — currently в `node_modules/` но НЕ в `dependencies` (CONTEXT D-06 augmented).
- **EAS OTA НЕ меняет `nativeApplicationVersion`** — header reflects binary version; корректная семантика для compat negotiation (OTA не может вводить native-side breaking changes).

**Enforcement (D-08 revised):**

- `services/backend/gateway/` — **Caddy-only directory** (Caddyfile + Caddyfile.prod + admin static HTML); НЕ Go-сервис. Прежний драфт CONTEXT'а предполагал Go gateway service — research выяснил что нет.
- Решение: shared `pkg/clientversion` Go библиотека (mirrors `pkg/ratelimit`/`pkg/permissions` shape); каждый сервис wrap'ит свой `http.ServeMux` в outermost mux wrap. Plan 01-02 (Wave 1, parallel to 01-01) реализует и монтирует.
- Single-source-of-truth сохранён: одна Go-lib, не дублируется по сервисам.

**Server response shape (per D-07, верно в `_shared/responses.yaml`):**

```json
{
  "error": "client_too_old",
  "min_version": "1.0.0",
  "force_update_url_android": "https://<domain>/android/manifest.json",
  "force_update_url_ios": "https://apps.apple.com/..."
}
```

Caddy reverse-proxies пропускают `X-Client-Version` без изменений (intercation
test в Plan 01-02 это валидирует).

**Mobile 426 handling:** `apiClient.ts` низшего уровня intercept'ит status 426
ДО любого 401-refresh-retry pathway; пушит `useForceUpdateStore.getState().set({...})`
с `{required: true, minVersion, forceUpdateUrl}`. `App.tsx` рендерит блокирующий
`ForceUpdateScreen` поверх `RootNavigator` пока `required=true`. Same UX path
будет переиспользован Phase 18 self-hosted Android update flow.

**Graceful-degrade в v1.0:** Missing/malformed `X-Client-Version` → server log
warn + pass-through (НЕ 426). Strict mode (reject malformed) — deferred в v1.1
(см. §Сценарии пересмотра).

### §3 Feature Flags

**Принято:** Postgres single-table source-of-truth + shared Go library
`pkg/featureflags` + 30-second in-memory cache per service (FNV-1a deterministic
percentage rollout) + mobile Zustand+MMKV mirror with 5-minute TTL + bundled
offline-first defaults.

**Backend (`pkg/featureflags`):**

- Migration `0021_featureflags.up.sql` (current latest on disk — `0020_auth_otp`; **`0021` not `0020`** per research correction; ранний CONTEXT-draft ошибочно говорил `0020`).
- Schema:
  ```sql
  CREATE TABLE featureflags (
    flag_name TEXT PRIMARY KEY,
    enabled_bool BOOLEAN NOT NULL DEFAULT false,
    rollout_percent INTEGER NOT NULL DEFAULT 0 CHECK (rollout_percent BETWEEN 0 AND 100),
    description TEXT,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_by_user_id UUID REFERENCES users(id)
  );
  ```
- Read-through cache 30s + `golang.org/x/sync/singleflight` для prevent thundering herd на cache miss.
- Percentage rollout = `FNV-1a(user_id || 0x00 || flag_name) % 100 < rollout_percent`. Deterministic per-user; same `(user, flag)` → same bucket across services. FNV-1a выбран над xxhash потому что stdlib + 2-3% better distribution xxhash'а не оправдывает добавление dep'а на нашем масштабе.
- Admin write: `Set(ctx, name, enabled, percent, actorID)` — UPDATE + invalidate local cache + audit.Log в same handler. Cross-service invalidation — best-effort via 30s TTL expiry (accept lag для kill-switch flags; NATS-broadcast invalidation — v1.1 если 30s lag bites).

**Admin UI:**

- Extension of `services/backend/gateway/admin/index.html` (vanilla HTML+JS, Phase 8/L precedent для reports / audit / abac sections — новая `<section>` для feature flags).
- Capability `featureflag.toggle` зарегистрирован в `pkg/permissions` + override в moderator/admin path.

**Mobile (`apps/mobile-rn/src/state/featureflags.ts`):**

- Zustand store с `persist` middleware → MMKV (mirror `settings.ts` pattern).
- `refresh()` — idempotent fetch с 5-minute TTL; network-error → keep cached/defaults; offline-no-cache → bundled defaults.
- `isEnabled(name)` — read из in-memory; falls back to bundled defaults.
- `clearAll()` — drop server-overrides + revert to defaults; called from auth logout.
- HTTP client: `featureflagsApi.ts` (mirror `xpApi.ts` pattern; returns `null` on error → store keeps cache).

**Bundled defaults** (`featureflags.defaults.ts`):

- `strava_oauth_enabled: false` — flipped ON when HEALTH-04 ships in Phase 11/12.
- `mapbox_sdk_v11: false` — flipped ON during Phase 13 soak.
- `release_channel_force_update: false` — emergency kill-switch for 426 UX.
- `tester_debug_logging: false` — opt-in per OBS-08.
- `crash_telemetry_opt_in: false` — opt-in per CRASH-04 (privacy first).

Все default OFF → predictable airplane-mode behavior + privacy-safe initial state.

## Альтернативы

| Опция                                                                         | Решение | Почему отклонено                                                                                                                                                                                |
| ----------------------------------------------------------------------------- | ------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **URL path versioning (`/v1/...`)**                                           | Reject  | Фрагментирует роуты по сервисам; forces big migrations при v2; header — industry-standard для client capability negotiation. (D-05).                                                            |
| **`oapi-codegen` / `openapi-typescript` codegen**                             | Reject  | Hand-written discipline проходит для team-of-2; добавляет toolchain complexity + CI surface. Revisit в v1.1 если hand-written drift bites. (CONTEXT §Deferred).                                 |
| **LaunchDarkly / Statsig / OpenFeature SaaS flag mgmt**                       | Reject  | External dep + ongoing cost + offline-debugging hard; v1.0 stays Postgres-self-hosted; revisit в v2.0+.                                                                                          |
| **Новый Go gateway service для version-check middleware**                     | Reject  | Удваивает ops complexity; conflicts с Phase 6 Caddy WAF; per-service mount via `pkg/clientversion` preserves single-source-of-truth через shared lib. (D-08 revised).                            |
| **Runtime route-registration wrapping для drift check**                       | Reject  | Fragile (требует instrumentation per service); AST parsing — loud + predictable. RESEARCH.md §Don't Hand-Roll явно отклонил runtime approach.                                                   |
| **xxhash для rollout**                                                        | Reject  | 2-3% лучше distribution но новая dep; FNV-1a — stdlib и well within tolerance на нашем scale (<1M users). Revisit если distribution variance станет проблемой.                                  |
| **A/B variant flags + per-user targeting в v1.0**                             | Reject  | v1.0 = boolean + percentage only. Variants + segments — v1.1 (D-12); v1.0 нужен kill-switch + staged rollout, не experimentation.                                                                |
| **Cross-service NATS-broadcast cache invalidation**                           | Defer   | 30s TTL expiry — best-effort; добавляем complexity только если измеряем real-world lag-pain (см. §Сценарии пересмотра).                                                                          |
| **Splitting в 0007/0008/0009 ADRs**                                            | Reject  | Три sub-decisions tightly coupled (delivered as Phase 1 одним milestone); три раздела в одном ADR — right granularity (D-20).                                                                    |

## Обоснование

**§1 API Contract Format.** Hand-written YAML — самая дешёвая инвестиция при
команде из 2 человек: editor support отличный, lint loud (`redocly lint` ловит
broken `$ref`s, missing schemas, malformed structures), drift check loud (`make
check-routes` exit 1). RESEARCH.md §Standard Stack confidence — HIGH: multi-file
с `_shared/` и cross-file `$ref` — established 2024+ pattern across openapi
community.

**§2 Version Negotiation.** Header transport + 426 — industry-standard (Strava,
Uber, Stripe APIs все так делают). `pkg/clientversion` shared lib mounted per-service
— единственный architecturally clean вариант когда edge — Caddy reverse-proxy
(нет Go gateway куда middleware прикрутить). Graceful-degrade на malformed header
— защищает от self-inflicted DoS если parser строгий и mobile-build шипнет битый
header'ed payload.

**§3 Feature Flags.** Postgres single-table — debuggable (SELECT + UPDATE для ops),
backup-friendly (один backup даёт snapshot всего matrix'а), self-hosted (no
external dep cost). 30s cache — proven pattern в `pkg/ratelimit` (Redis-down →
allow=true graceful) + `pkg/audit` (querier interface). FNV-1a deterministic
rollout — same `(user, flag)` → same bucket across services даёт mobile/backend
consensus без RPC. Offline-first mobile defaults — closed-beta пользователи
часто в airplane mode (горы / бег за городом) — нужны predictable bundled values.

## SCP-throughout cross-cut

Per CONTEXT D-21 — SCP-over-SSH с deploy key scoped path — это cross-cutting
deploy principle для обеих deployment веток v1.0:

- **Backend deploy (Phase 3 INFRA)** — Ansible playbooks SCP бинарей + systemd units на VPS через scoped deploy key (key restricted to `/var/www/...` / `/etc/systemd/...` paths via authorized_keys `command=` или `ForceCommand`).
- **Android APK distribution (Phase 18 AND-DIST)** — APKs SCP'ятся на VPS `/var/www/android-updates/` (VPS-direct **not** Hetzner Storage Box — CONTEXT D-22 correction; ROADMAP fix deferred to discuss-phase 18); Caddy serves the path directly с signed-URL gating.

ADR-0007 устанавливает принцип:

- Один deploy mechanism (SCP-over-SSH) — same key management, same audit trail, same revocation surface.
- Scoped keys — никаких god-keys на VPS; per-channel keys (backend / android-updates) с filesystem-path restriction.

Phase-specific механика — в `.planning/phases/03-*` (Ansible inventory + key
distribution) и `.planning/phases/18-*` (CI workflow upload + manifest signing).
Этот ADR не дублирует их.

## Сценарии пересмотра

| Trigger                                                                     | Действие                                                                                                                                |
| --------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| Hand-written YAML drift bites (developer skips `redocly lint` + push slips) | Введём `oapi-codegen` для Go стабов (контракт-as-source). Revisit в v1.1.                                                                |
| 426 graceful-degrade пропускает невалидный header в продакшен               | Включим strict mode (reject malformed) + добавим pre-deploy schema-check в CI. Revisit в v1.1.                                          |
| 30s feature-flag lag вызывает inconsistent rollout                          | Добавим NATS-broadcast invalidation (subject `featureflags.invalidate.<name>`); cache slot reset on subscribe. Revisit в v1.1.           |
| A/B testing нужен в v1.1                                                    | Расширим schema до `(flag_name, variant_name, percent)` + добавим variant column в `pkg/featureflags`; mobile mirror enums vs booleans. |
| Internal service-to-service typing pain                                      | gRPC контракты внутри cluster (NATS остаётся для events); revisit в v1.1+.                                                              |
| Mapbox costs > acceptable на 10k MAU                                        | Map provider migration (см. ADR-0001 §Сценарии пересмотра); orthogonal к этому ADR.                                                     |
