# `tests/runs/` — Phase 1 Field-Test Artifacts

Этот каталог содержит артефакты прогонов полевого тестирования Phase 1
(см. [`../FIELD_PROTOCOL.md`](../FIELD_PROTOCOL.md)).

**REQ-IDs:** PHASE1-01, PHASE1-02, PHASE1-03, PHASE1-04.
**Связанный план:** [`.planning/phases/01-validate-close-territory-core/01-09-PLAN-field-test-execution.md`](../../.planning/phases/01-validate-close-territory-core/01-09-PLAN-field-test-execution.md).
**Решение D-03 (CONTEXT.md):** результат каждого прогона = (a) строка в
`tests/FIELD_PROTOCOL.md`, (b) GPX-файл здесь, (c) фото батареи для T6/T8.

## Соглашение по именам путей

```
tests/runs/<device>/<test>/<timestamp>.gpx
tests/runs/<device>/<test>/battery_before.jpg     # T6, T8
tests/runs/<device>/<test>/battery_after.jpg      # T6, T8
tests/runs/<device>/<test>/screenshot_end.png     # опционально
```

### `<device>`

Канонические значения — фиксируем заранее, чтобы FIELD_PROTOCOL.md строки
ссылались на конкретный путь:

| `<device>` | Что это | Когда |
|------------|---------|-------|
| `pixel` | Google Pixel (модель указать в FIELD_PROTOCOL.md «Notes») | Task 2 — выполняется первым (D-02) |
| `iphone` | iPhone (модель + iOS в Notes) | Task 3 — gated на Xcode + Plan 08 Task 4 |
| `xiaomi-redmi9` / `realme-c25` / `oppo-a78` / `honor-x8` | Конкретная модель китайского OEM | Task 4 — gated на приобретение устройства |

Если устройство сменилось внутри одного класса (например, был Pixel 6, стал
Pixel 8) — используйте суффикс: `pixel-6`, `pixel-8`. В FIELD_PROTOCOL.md
явно указывайте модель + версию ОС в колонке «OS».

### `<test>`

Точно: `T1`, `T2`, `T6`, `T7`, `T8`, `T9`. Не пишите `t1` или `T01` —
автотест в `01-09-PLAN-field-test-execution.md` ищет по grep ровно эти
строки.

### `<timestamp>`

Формат `YYYY-MM-DD-HHMM` (локальное время старта). Пример:
`2026-05-15-0930.gpx` — старт прогона 15 мая 2026, 9:30 утра.

Несколько прогонов одного теста в один день: добавьте суффикс `-2`, `-3`:
`2026-05-15-0930.gpx`, `2026-05-15-1500-2.gpx`.

## Что коммитить, что НЕ коммитить

**Коммитить** (исключения уже добавлены в `.gitignore` строки 102–124):
- `.gitkeep` — маркер директории
- `README.md` — этот файл
- `**/*.gpx` — экспорт трека из приложения через Share API
- `**/*.md` — заметки прогона (опционально, кратко)
- `**/*.jpg`, `**/*.jpeg`, `**/*.png` — фото батареи / скриншоты

**НЕ коммитить:**
- Сырые JSON-логи pipeline (`log.json`) — они могут содержать timestamps
  с точностью до миллисекунд + raw GPS-координаты. Если нужно для отладки —
  кладите в `tests/runs/<device>/<test>/log.json` и явно gitignore через
  `.gitignore` (на текущий момент `*.json` не в исключениях).
- Видео экрана — слишком большие для git.
- Любые личные данные (контакты, фото лица, и т.п.).

## Privacy boundary (T-01-09-01)

GPX-файлы содержат **сырые GPS-координаты** ваших пробежек —
их адекватность для коммита в git зависит от приватности репозитория.

- Сейчас: репозиторий приватный (`PROJECT.md` §Scope), GPX можно коммитить.
- После Phase 4: появится privacy-zone masking, на момент открытия репо
  GPX-экспорты будут обрезаться по home/work зонам — старые файлы должны
  быть либо удалены, либо перегенерированы из исходных сессий с применением
  privacy clip.

Если **возникают сомнения** (например, GPX начинается у подъезда дома) —
**не коммитьте** этот конкретный файл. Достаточно строки в
`FIELD_PROTOCOL.md` с метриками; GPX можно держать локально до Phase 4.

## Шаблон прогона (опционально)

См. `REPORT_TEMPLATE.md` в `FIELD_PROTOCOL.md` (раздел «Шаблон отчёта»).
Для краткости новый протокол Plan 09 использует только **строку в таблице**
+ ссылку на GPX — REPORT.md внутрь каждой папки прогона создавать
**не обязательно**. Если прогон шёл нештатно (упало, восстанавливалось из
crash recovery, OEM-killer сработал) — добавьте `NOTES.md` рядом с GPX
и сошлитесь на него в колонке «Notes» таблицы.
